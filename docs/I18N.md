# Hebrew and right to left

Owner's request (2026-11-26): the whole site in Hebrew, with the problems always in English. The
default follows the device (Hebrew when the browser's first language is Hebrew); a switch in the
header (the account sheet on a narrow phone), Profile and the palette changes it.

## How it works

- `src/js/lang-boot.js`, a classic script in the `<head>` of every page, sets `lang` and `dir` on
  `<html>` before the first paint and keeps `window.lfbLang` (`current`, `set`, `button`). A choice is
  saved (`lfb:site-lang`) and reloads the page.
- `ui/dom.js`:
  - `tr(en, he)` is **shell** copy in the site language: header menus, the palette, dialogs, toasts,
    the bell. Hebrew everywhere on the Hebrew site, over the problem screen too.
  - `tp(en, he)` is **page** copy in the page's language (`pageLang()`): everything drawn inside
    `#view`. It follows the route, so a shared piece shows English on a page not translated yet and
    in the exam room.
  - Pure modules (`data/*.js`) take the language as a parameter (`lang = 'en'`) and never read it.
- `main.js` route table: the fifth field marks a route drawn in Hebrew. Any other route keeps `#view`
  at `dir="ltr" lang="en"` on the Hebrew site (`setViewLanguage`), so a page never shows English in
  a mirrored layout. Every browse page (including `#/map`) is marked Hebrew; only the exam room
  stays English.
- **The exam room stays English and left to right**: the problem screen and the timed sessions
  (`renderWorkspace` sets `dir="ltr" lang="en"` on its root). Problems, code, test cases and verdicts
  read as they will in the real interview.
- CSS uses logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`), so
  the layout mirrors by itself. Physical `left` / `right` stay only where a position is computed in
  pixels (the nav glider, tours, the map, the burst, the reminder clock, switch knobs) or for
  `left: 50%` centring. Code, the map canvas and the reminder clock are `direction: ltr` inside a
  Hebrew page. Icons drawn as backgrounds get an `[dir='rtl']` rule at the end of `app.css`.

for the Hebrew site, so its levels read קל / בינוני / קשה there. A problem's difficulty stays Easy /
Medium / Hard, as on LeetCode.

Stay in English (Latin script) on the Hebrew site: topic and subtopic names (Two Pointers,
Dynamic Programming), difficulty (Easy, Medium, Hard), verdicts (Accepted, Wrong Answer, Time Limit
Exceeded), language names (JavaScript, Python 3), company names, keyboard keys, and everything in the
exam room.

## Voice

- Buttons in the infinitive, which is also gender neutral: "להתחבר", "לנסות שוב", "לפתוח את המפה".
- Body text without gendered second person where it can be avoided: "כדאי לבדוק את החיבור", not
  "תבדוק" / "תבדקי". Where a second person is unavoidable, prefer a plural or a noun ("ההתקדמות שלך").
- Short and direct, as in English. No em dashes, no exclamation marks except a genuine success.
- Numbers as digits. A Latin term inside Hebrew text is fine as is; the browser isolates it.
- Same meaning as the English, not a word-for-word copy: it should read as written in Hebrew.
- Weeks start on Sunday in Hebrew (`calendarWeeks({ weekStart: 0 })`), as every Israeli calendar does.
- Hebrew is never letter-spaced, and labels set in mono use the sans in Hebrew (JetBrains Mono has no
  Hebrew letters and a wide space); code stays mono.
- The theme-switch quips have their own Hebrew lines, each approved by the owner
  (`THEME_QUIPS_HE` in `data/theme-quips.js`); new lines in either language need the owner's
  approval. Guided tours (`data/tours.js`) carry Hebrew copy for every browse and setup page,
  keeping the exam-room tours (`workspace`, `mentor`) in English. Web Push reminders store the
  user's site language in `push_settings.lang` (default `'en'`) and send both scheduled reminders
  and the test push in that language (`deploy/supabase/functions/push/core.js`).

# Changelog

## [Unreleased]

### Changed
- The legacy `milestone` field is gone from all problem files, the catalog and the problem format (no view has read it since the essential path replaced the milestones).
- Growth estimate: one slow (or fast) middle size no longer spoils a 4-size measurement. With exactly 4 sizes, an interior outlier is dropped when the other 3 fit tightly; the first and last sizes are never dropped there (a slow last size can be real growth). Outliers are now judged against the line through the other sizes. A linear solution with one slow middle size read "timings too noisy" before and reads "matches" now; a slow last size, a real bend and noise everywhere still do not match (ADR 0004 amended).
- Learning Path is the essential path: 131 problems in 6 tiers and 26 topics in prerequisite order, easy to hard inside each topic, with progress per tier and topic, the subtopic of each problem, and a Next up button to the first unsolved problem. Replaces the 4 temporary milestones (`src/js/data/curriculum.js` removed, and the dashboard's milestone column with it). Data: `src/js/data/essential-path.json`, built by `scripts/content/build-meta.mjs`.
- First Match Index is Medium (was Easy): with our limits it needs KMP.

### Fixed
- C# on the remote runner failed on "cannot open the device or file specified: 'NuGet-Migrations'". Since .NET 8.0.42x (a security fix) named mutexes live in `$XDG_RUNTIME_DIR`, else `$HOME/.dotnet`, and Piston's job users have neither. Each job now gets its own `HOME`, `XDG_RUNTIME_DIR` (mode 700), temp and NuGet directories; reproduced and verified as an unknown uid with the exact package scripts. Diagnostics IPC is off too.
- C# on the remote runner failed to compile under the real sandbox (first live deploy): .NET's W^X double mapping sizes a shared file past isolate's per-file limit and every dotnet process died with SIGXFSZ. `DOTNET_EnableWriteXorExecute=0` in the package environment; reproduced and verified with `ulimit -f` (exit 153 before, 0 after). The local stand-in had no file-size limit, so it never showed.
- Growth estimate: a size that runs uniformly slow for a while (a JIT tier change) could leave the estimate "too close to call". The browser now re-measures once when the first pass is inconclusive for a transient reason and the retry fits the 5 s budget (`shouldRetryGrowth`). The e2e quadratic example shifts elements in JavaScript instead of a native `splice`, so it is quadratic beyond doubt.
- CI hit its 15-minute limit: verifying 133 problems in 8 languages one after another takes over 30 minutes. Solutions now verify in one parallel job per language (`VERIFY_LANGUAGES`), and `tests/ci.test.js` fails if the matrix misses a language. Toolchain probes run once instead of once per problem.
- Database sync ran out of memory at 133 problems: `scripts/db/export-sql.mjs` built the whole script (about 370 MB, mostly test data) as one string. It now streams batched inserts and waits on a full pipe.
- Python names for signatures with acronyms: `lengthOfLIS` became `length_of_l_i_s`; an acronym is now one word (`length_of_lis`). No existing problem changes.
- Java verifier reused one `Solution` object for all 15 cases, so state left in instance fields leaked between cases (found with an imported Subsets solution). It now creates one per case, like LeetCode and the C++ and C# harnesses.
- Uncaught "Canceled" errors when leaving a problem: Monaco cancels in-flight work on close, and its scripts loaded without CORS, so the errors were muted and impossible to handle. Monaco now loads with CORS, editors are disposed before their models, and only Monaco's exact cancellation error is ignored.
- ADR 0002: PostgreSQL on Supabase as the runtime store, git as the content source of truth. `db/schema.sql` (18 tables, row level security: hidden test cases and solutions never reach clients, `reveal_solution()` marks a problem assisted). `scripts/db/export-sql.mjs` syncs git into the database without touching user data. `scripts/db/check-schema.sh` (`npm run check:db`, in CI) verifies all of it against a throwaway PostgreSQL with the real content.
